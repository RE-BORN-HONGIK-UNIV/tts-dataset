# synthetic_v1 품질관리(QC) 프로토콜

## 1. 목적과 범위
본 프로토콜은 synthetic_v1에서 생성한 TTS 음성 파일의 기술적 완전성과
목표 연장 표기의 청취상 실현 여부를 점검하기 위한 것이다.

이 QC는 실제 사용자의 불안도, 정신건강 상태, 면접 역량, 말더듬 또는
임상적 유창성 장애를 평가·진단하지 않는다.

## 2. QC 단계
1. 기술 QC
2. 자동 음향 QC
3. 청취 QC
4. manifest 및 로그 상태 확정

## 3. 기술 QC
각 WAV 파일에 대해 아래를 확인한다.

| 점검 항목 | 통과 기준 | 실패 시 처리 |
|---|---|---|
| 파일 수 | 497개 계획과 일치 | 누락 파일 재생성 |
| 파일 열기 | WAV 디코딩 가능 | 재생성 |
| 파일 크기 | 0 byte 초과 | 재생성 |
| 채널 | mono | 변환 또는 재생성 |
| sample rate | 프로젝트 설정값과 일치 | 재생성 또는 표준화 |
| 파일 길이 | 0초 초과 | 재생성 |
| clipping | 샘플 peak가 허용 범위를 넘지 않음 | 재생성 또는 제외 |
| 파일명 | 명명 규칙 충족 | 이름 수정 및 manifest 동기화 |

> sample rate와 peak 허용 범위는 실제 Typecast 출력 사양 및 프로젝트의
> QC 스크립트 구현값을 기록한 뒤 확정한다. 현재 값이 정해지지 않았다면
> 임의의 수치를 기준으로 문서화하지 않는다.

## 4. 자동 음향 QC
- 목표 위치 전후의 RMS 또는 short-time energy 변화를 기록한다.
- 전체 길이, 무음 비율, peak, RMS를 기록한다.
- 자동 측정값은 이상 후보를 선별하는 용도이며, 연장의 자연스러움이나
  합성 오류를 단독으로 확정하지 않는다.
- 경고 파일은 청취 QC 표본에 우선 포함한다.

## 5. 청취 QC
### 평가 항목
| 항목 | 질문 |
|---|---|
| 자연스러움 | 전체 발화가 청취상 지나치게 부자연스럽지 않은가? |
| 연장 인지 | 목표 위치에서 상대적 길이 증가가 들리는가? |
| 연속성 | 목표 단어 전후가 끊기지 않고 이어지는가? |
| 오류 여부 | 반복, 재시작, 명백한 분절, 발음 붕괴가 있는가? |

### 판정
| 판정 | 의미 | 처리 |
|---|---|---|
| pass | 목표 연장이 인지되고, 중대한 오류가 없음 | 학습·검증 후보 유지 |
| review | 판단이 어렵거나 경미한 부자연스러움 | 추가 청취 또는 재생성 비교 |
| fail | 반복·분절·발음 붕괴·목표 연장 미인지 | 학습 후보에서 제외 |

### 기록 원칙
- 청취자 ID, 점검 일시, 파일명, 항목별 결과, 최종 판정, 메모를 기록한다.
- 최소 두 명이 독립적으로 청취한 뒤 불일치 파일을 재검토한다.
- 청취 결과는 `metadata/prolongation_v1_qc.csv`에 기록한다.

## 6. 결과 반영
- 기술 QC 실패: 재생성 또는 파일 제외 후 원인을 generation log에 기록한다.
- 청취 QC fail: WAV를 삭제하지 않고 `excluded` 상태로 보존한다.
- 모델 학습 시에는 `pass` 파일만 사용한다.
- manifest에는 생성 상태와 QC 상태를 별도 열로 기록한다.

## 7. 한계
- 합성 TTS 기반 연장은 실제 자발화 연장의 음향·언어적 다양성을 모두
  대표하지 않는다.
- 청취 QC의 평가는 합성 품질에 대한 운영적 판단이며 임상 진단이 아니다.
- QC 통과는 실제 면접 상황에서의 모델 성능 또는 사용자 일반화를 보장하지 않는다.
